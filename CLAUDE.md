# The Tesla Thesis (TTT)

> **This document must be updated whenever TTT content, features, or pipelines change.**

Single-page Tesla & SpaceX intelligence dashboard with hacker/terminal aesthetic. SpaceX became first-class content 2026-07-16 (own categories, `[TESLA]`/`[SPACEX]` topic badges, relevance gate passes SpaceX).

## Tech Stack
- Vite + React + TypeScript + Tailwind CSS v4
- JetBrains Mono font, #00ff41 green accent, #0a0a0a background

## Architecture
- Everything lives in `src/App.tsx` — single-page, no routing
- Three visible tabs in the header nav: Daily Feed (news + stock + merger odds; robotaxi-counts tile hidden 2026-07-03 — upstream frozen, see Robotaxi Tracker Scrape), INTERVIEWS (Interview Archive — primary-source summaries with tracked claims; also reachable via `#interviews`; each interview is deep-linkable at `/i/<slug>/` with its own OG preview card), TSLA_DATA (quarterly metrics). Weekly Tesla Briefs are also deep-linkable at `/w/<date>/` (date = the brief's Monday): the static shell + OG card mirror the interview pattern, and the SPA opens the brief popup over the Daily Feed on load (`src/components/Feed/weeklyRoute.ts`). Official Tesla releases (channel `tesla` — earnings, P&D, impact reports) are likewise deep-linkable at `/t/<slug>/` since 2026-07-07 (slug emitted by `build-news.js`, route in `src/components/Feed/teslaRoute.ts`, OG card `public/og/tesla-<slug>.png`). SUPPORT_TTT header button removed 2026-06-12 (clicks never converted to donations). Valuations section is built but hidden from the nav — reachable via the `#valuations` URL hash. Houses the live Robotaxi DCF; EV / Optimus / Energy / AI compute models planned.
- Stock prices: stock-proxy on Mac Mini (Finnhub upstream) → `wss://api.theteslathesis.com`. **Two tickers since 2026-08-03 — TSLA and SPCX** (SpaceX, NASDAQ, IPO'd 2026-06-11), multiplexed over one socket: the client subscribes per symbol and the proxy tags each quote message with `symbol` at the top level (`{type:'quote',symbol:'SPCX',data:{…}}`), which `useStockQuote` demuxes into a `quotes` map keyed by symbol. Subscription filtering is enforced proxy-side (a TSLA-only subscriber never receives SPCX). Ticker list lives in `SYMBOLS` in `src/components/Stock/helpers.ts` — the one place to add a third. Widget header is `STOCK PRICES` (was `NASDAQ:TSLA`)
- Stock chart: **removed 2026-08-03** with the two-ticker layout — `StockChartPanel.tsx` deleted, `RANGES` and the TIMEFRAME dropdown gone, and the `Chart Timeframe` Plausible event retired. The stock widget now shows price + change + OPEN / PREV CLOSE / HIGH / LOW per ticker. The proxy's `/chart` endpoint stays live: `scripts/pipeline/stock-data.js` still fetches it every pipeline run for TSLA price grounding. Lightweight Charts v5 is still a dependency — the merger-odds card uses it
- Content: Mac Mini yt-transcripts → git push → `scripts/build-news.js` → `src/data/news.json`
- Only `_summary.txt` files are processed, deduplicated by title+date

## Design Rules
- Sharp corners only, no rounded borders
- Monospace font everywhere, green highlights on dark background
- Full words always (OPEN, PREV CLOSE, HIGH, LOW) — never abbreviate
- Stock price + merger odds only on Daily Feed tab (robotaxi counts tile hidden 2026-07-03)
- Popups use blurred semi-transparent overlay (bg-bg/60 backdrop-blur-md); popups reachable from multiple mount points render via createPortal to body
- Amber (#ffb000) marks interview/primary-source content (feed teaser rows, admin queue badge); green stays for live/interactive
- Topic badges after feed titles + in the article popup: `[TESLA]` #d0bd5c (faded yellow), `[SPACEX]` #4d9fff, both when topic `both`, and `[OFFTOPIC]` in dim grey (`text-text-dim`, #666666) when topic `none` (`topicTag()` + `TOPIC_STYLE`/`TOPIC_LABEL` in `src/components/Feed/helpers.tsx`, driven by the article `topic` field). `[OFFTOPIC]` is a **demotion marker, not an identity badge** — grey was chosen so it recedes rather than competing with the two company colors (red = errors, amber = interview/primary-source + stale, green = live/interactive were all already taken). No badge on legacy summaries (null topic) or TTT briefs
- Feed teaser rows open the interview popup in place (never switch tabs from a feed click)
- Coverage categories (`Categories:` header, 7 Tesla + 5 SpaceX) reach the UI since 2026-08-31: `build-news.js` whitelists them against `CATEGORIES` in `scripts/pipeline/config.js` into each article's `categories` field (canonically ordered, so SpaceX categories always render last) and ships the canonical list as `categoryOrder` in `news.json` so the frontend has no second copy to drift. Surfaced as a `CATEGORY:` dropdown beside the channel `FILTER:` on the Daily Feed (options derived from categories actually present) and as clickable chips in the article popup that close it and filter the feed to that category (`Category Filter` Plausible event, fired once via `applyCategory` in `src/App.tsx`). Category and channel filters AND together, so the feed has an empty state — placed above SHOW OLDER, never replacing it, since a narrow category like `SpaceX — Launch Business` routinely has nothing in the last 7 days. Articles predating the header (pre-2026-06-24 for channels, plus the TTT briefs, whose header says "Weekly Brief" and is whitelisted away) carry no categories and appear only under `CATEGORY: [ALL]`

## Stock Price Logic
- Applies per ticker (TSLA and SPCX dim independently); the shared session line reads "waiting for live" only when neither has ticked
- Pre-market: show last close (dimmed) immediately, switch to live when WebSocket delivers
- Pre-market % change = vs last session close (q.c), not previous day close (q.pc)
- REST never overwrites WebSocket price once live

## Summary Pipeline (`scripts/pipeline/`)
Transcript-driven summarization pipeline (transcripts pushed directly to repo by Mac Mini):
- `run.js` — main orchestrator (scan unsummarized transcripts → Claude Batch API → write summaries → rebuild news.json)
- `exec-summary.js` — Daily Tesla Brief aggregating all `_summary.txt` for a date into `news/YYYYMMDD_ttt_00_executive_summary.txt` (filename kept; user-facing Title is "Daily Tesla Brief"). Direct API (Sonnet 5, thinking disabled). Runs only on the 00:15 and 07:15 UTC pipeline executions. **UNPUBLISHED since 2026-08-28 — this is now a pipeline intermediate, not reader-facing**: `build-news.js` drops every `_ttt_00_executive_summary` file in the same `.filter()` as the moderation gate, so it never reaches the feed (reader opens had fallen to 25 visitors/month, 6.9%, from 78 in May). It must keep being generated regardless, because `weekly-summary.js` builds the Weekly Brief ONLY from these files and silently skips the week if fewer than 3 exist — they compress a week of raw summaries ~8.5× (438KB/86 files → 51KB/7 files), which is why the weekly costs only ~$0.48/mo. **Never drop the daily brief without first rewriting `collectDailyBriefs()`.** The 07:15 pass now runs with `--skip-if-exists` and only BACKFILLS when the 00:15 run produced nothing, instead of regenerating to fold in late material (~$3.53 → ~$1.75/mo; it was running 53× over 28 days in 2026-08). The 07:15 slot was kept rather than deleted because GitHub skipped the 00:15 cron outright on 2026-08-27 and mis-attributed the delayed 08-28 run — a plain removal would have lost two briefs in one week, and the weekly step is `continue-on-error`, so that failure would have gone green. Files stay in `news/` either way; reverting the feed change is deleting one check.
- `prompt-exec.md` — prompt for the Daily Tesla Brief (Brief bullets + category sections + notable quotes). Includes the SpaceX categories since 2026-07-16; Brief bullets lead with Tesla when importance is comparable
- `weekly-summary.js` — Weekly Brief aggregating the prior 7 daily briefs (Mon-Sun) + last 4 weekly briefs (continuation context) into `news/YYYYMMDD_ttt_99_weekly_brief_summary.txt`. Direct API (Sonnet 5, thinking disabled). Primary trigger since 2026-07-06: the Mac Mini dispatches `daily-pipeline.yml` (`workflow_dispatch`, `mode=direct`, `skip_exec=true`) at 05:45 UTC Mondays — GitHub's scheduler delays cron runs ~4–4.5h regardless of slot (the old cron landed ~10:00 UTC every week), while dispatch runs start in seconds. The Monday-only cron `45 5 * * 1` is kept as a delayed fallback; the script skips if the week's brief file already exists (`--force` to regenerate). Besides the brief it writes a `..._weekly_brief_reddit_bullets.txt` sidecar (expanded Brief bullets from the prompt's `<reddit_bullets>` block; ignored by `build-news.js`, consumed by `reddit-weekly.js`). Output is post-processed by `normalizeSeparators()` to guarantee exactly one `---` between `## ` sections — the model emits them inconsistently and `reddit-weekly.js` keys on them.
- `reddit-weekly.js` — deterministic formatter (no LLM) that converts the latest Weekly Brief into a copy-paste Reddit post file (`data/reddit-weekly/YYYY-MM-DD.md`, target r/teslainvestorsclub) with TWO variants: **Variant A** (link-embed experiment, added 2026-07-02) = the `/w/<date>/` deep-link URL (paste + Reddit "Link Embed" → OG card) followed by "This week:" + the EXPANDED Brief bullets from the `news/YYYYMMDD_ttt_99_weekly_brief_reddit_bullets.txt` sidecar (written by `weekly-summary.js` from the `<reddit_bullets>` block the weekly prompt now emits in the same LLM call — same headline items, each expanded to ~150–190 chars) and NOTHING else (no detail sections, no closer line — user direction 2026-07-06). r/teslainvestorsclub requires ≥1000 chars of body text once any body text is present (rule discovered on the 2026-07-06 post; the site's short Brief bullets alone are ~500 chars). The file header prints the Variant A char count (excl. the URL), the script warns loudly if under 1000 or if the sidecar is missing (falls back to short bullets → expand manually); **Variant B** (fallback) = the original full-text post with the TTT link in the Brief heading (top-of-fold, single outbound link). Runs on the Monday cron after the weekly brief, the news.json rebuild and the OG card render. If a transform's pattern doesn't match (source format drift), it warns loudly: `!! WARNING` lines in the output file header + `::warning::` GitHub Actions annotation. If the week's OG card (`public/og/weekly-<date>.png`) is missing it adds a `>> TODO` reminder line to the header (run `npm run og-images`, commit + push, wait for deploy before posting Variant A) — since 2026-08-03 the pipeline renders that card two steps earlier, so the reminder now only fires when the render step actually failed.

Continuation Discipline section added 2026-07-13 after the 07-13 brief re-headlined the prior week's stories (Q2 deliveries, Miami launch, Fremont Optimus line): already-told stories from the 4 prior briefs (all injected, not just last week's) may only appear as deltas leading with the new fact; Bear Case items must be removed from their thematic category. Includes the SpaceX categories since 2026-07-16; Brief bullets lead with Tesla on comparable importance, and `<reddit_bullets>` are reordered Tesla-first (SpaceX bullets last, droppable if Tesla alone clears the 1,050-char minimum — the post targets r/teslainvestorsclub)

## Alerting & Notifications
GitHub email was ~3 notifications/day (2026-08-10); every recurring notifier now uses a **rolling issue** instead of one issue per event. Issue *creation* and *comments* notify watchers, but **body edits do not** — so a rolling issue costs one notification ever, then stays current silently.
- `scripts/rolling-issue.cjs` — shared `upsertRollingIssue()` helper: find the open issue by label + STABLE title, rewrite its body, create only if absent. `body` may be a function of the existing body (the failure log prepends and keeps the last 15 entries). **Must stay `.cjs`** — package.json is `"type": "module"` and actions/github-script's `require()` is CommonJS. Any job using it needs `actions/checkout`.
- Rolling issues: **Content moderation queue** (whole standing queue, so console decisions drop off by themselves), **Daily pipeline: failure log**, **Content freshness: unsummarized transcripts**. Leave them open — closing just makes the next run create a fresh one.
- **`interview-lead` is the one notifier that still creates an issue per event** — deliberate, it's the alert the user wants by email.
- GitHub's built-in Actions run-failure email is off at the *account* level (github.com/settings/notifications → Actions), not in repo config.
- Consequence accepted by the user: no active alert on pipeline failure — it surfaces at the next session sync or in the rolling issues.

Prompt mitigations for Sonnet 5 quirks: unresolvable-garble fallback rule (refer generically, never quote garbled forms) and output-tightness guidance. `prompt.md` also carries a context-dependent caption-garble hint (added 2026-07-17): auto-captions sometimes render "Cybercab" as "Cybertruck" — correct silently only when the context is unambiguously robotaxi deployment (never a blanket swap; both are real products). **Hardened + extended 2026-08-14** after the 08-13 Herbert summary hedged twice ("85 Cybertrucks/Cybercabs") and the hedge propagated into that day's Daily Brief: the source is machine-translated and garbled the term in all 19 mentions, and the model corrected 17 but slashed 2. `prompt.md` now bans naming both products (no slash or parenthetical alternative), requires consistency across bullets/quotes/data lines, states that this contextual judgment overrides the mechanical `CORRECTIONS` list (which maps `cyber truck` → `Cybertruck` and cannot see context), and tells the model to weight the piece's title/subject over per-mention repetition when a source garbles every instance. The rule is now in `prompt-interview.md` too (with a carve-out: never alter words inside verbatim quotes — paraphrase instead), and both aggregators (`prompt-exec.md`, `prompt-weekly.md`) must resolve a slashed pair to one name rather than carry it forward. **Attribution/quote-integrity rules added to all four prompts 2026-07-13** after an Electrek editorial assertion escalated through summary→daily→weekly into a fabricated Tesla "admission" (quote marks added around a paraphrase, attribution stripped): summarizers must keep unsourced "company admitted X" claims attributed to the outlet/host, aggregators must never strip attribution (keep it or drop the claim), and quotation marks are only for verbatim source text. **Arithmetic-consistency rule added 2026-08-03** (4 summarizers + both aggregators) after the 08-03 Herbert summary reported a speaker's out-loud miscalculation as fact — "$1.6B Space Force contract, 18 Falcon 9 launches, roughly $1 billion per launch" (actual ≈$89M; the speaker said "almost a billion dollars a launch" twice and built a profitability claim on it). Summarizers must now verify figures whose relationship is a simple division/multiplication against the source's own stated inputs, report the correct arithmetic, and attribute the speaker's number where their conclusion rests on it rather than silently repeating or dropping it; aggregators must not propagate a derived figure that disagrees with the inputs quoted beside it. **Two evidence-integrity rules added 2026-09-03** (4 summarizers only — the aggregators behaved correctly and were left alone) after the 09-02 jobhakdi Cybercab summary shipped two bad statements. (a) *Claim vs. its own cited evidence*: the host said a Texas VIN reading of "241" confirmed his earlier call of "over 2,000 robotaxis deployed", and the summary relayed the inference as connective tissue ("which he says confirms") — correctly attributed, but with nothing flagging that 241 is a VIN sequence number and an order of magnitude short. The 2026-08-03 arithmetic rule is scoped to division/multiplication and never fires on a magnitude-or-kind mismatch, so this generalises it: before writing that something "confirms"/"proves"/"shows" a claim, check the cited figure supports it in **both magnitude and kind** (a sequence or ID number is not a count; a registration is not a deployment), else split claim and figure into two attributed items and say the figure does not establish the claim. (b) *Never bind a figure to a subject the source does not clearly bind it to*: the transcript's mangled "Tesla will charge and bypass Whimo, the 30,000 number of cyber caps" attaches 30,000 to **Cybercabs**, and the summary rebound it to Waymo as "Waymo's fleet size (which he puts around 30,000 vehicles)" — a clean, checkable, ~8x-wrong third-party statistic asserted in the host's name (Waymo is under 4,000; that day's own Daily Brief said so from another source). The existing "reflect the ambiguity" rule did not fire because the rewrite no longer looked ambiguous. The new rule names third-party statistics (competitor fleet size, revenue, headcount, valuation) as the high-risk case and requires dropping the number or going qualitative rather than picking a subject — explicitly **not** licence to substitute the correct figure from training data, since `Grounding Rules` still bars importing outside data. Neither claim reached the Daily or Weekly Brief; the 09-02 summary was hand-corrected the same day. Summaries match existing `_summary.txt` format.

## Robotaxi Tracker Scrape (`scripts/scrape-tracker.js`)
Scrapes RobotaxiTracker.com via Playwright/Chromium and writes:
- `src/data/knowledge-base.json` — Robotaxi > fleet_deployment composite area (fleet_count, unsupervised_count, service_area trackers)
- `data/counts.json` — bare unsupervised count. Includes `data_as_of` = the date the total last *changed* (from KB `unsupervised_count.current.date`, which only advances on a real change). The `RobotaxiCounts` tile bases its STALE badge on data-change age, not `fetched_at` — the scraper keeps fetching successfully even while the upstream source is frozen, so fetch freshness ≠ data freshness. ## Merger Odds (`scripts/fetch-merger-odds.js`)
Fetches SpaceX-Tesla merger announcement odds from Polymarket's public Gamma API (plain GET, no auth, no Playwright) and writes `data/merger-odds.json`. The 1D/7D/30D deltas are computed in-script from the CLOB price-history series (`clob.polymarket.com/prices-history`, `interval=1m&fidelity=60`), NOT taken from Gamma's `oneDay/Week/MonthPriceChange` fields — those are dropped for thin markets when the change is ~0, which is indistinguishable from "no history". Computing from history lets the card distinguish a genuinely flat window (`0`) from a window with no anchor / market younger than the window (`null` → "—"). Falls back to Gamma's precomputed fields if a history fetch fails. Since 2026-07-03 the fetcher also persists a daily-downsampled 30-day `history` array (`[unixSeconds, yesPrice]` pairs) per market. Rendered by `src/components/MergerOdds/MergerOddsCard.tsx` as the second of two Daily Feed tiles (desktop: 2-col grid next to the stock widget; mobile: 2nd swipe panel). The JSON keeps all deadline markets, but the card shows only the farthest-deadline market that is **also liquid**: volume ≥ `max($1k, 10% of the busiest market's volume)` (`LOW_VOLUME_USD` + `MIN_VOLUME_SHARE` in `MergerOddsCard.tsx`; currently Dec 31 2026 at ~$131k). The relative share was added 2026-08-21 — the original flat ≥$1k bar was set when the event had two markets, and when Polymarket opened four 2027 deadlines on 08-14 the week-old Dec-2027 market ($8k volume, 8 days of history) cleared it and stole the card from the Dec-2026 market it had tracked for months. A share of the leader scales with the event instead of needing a hand-tuned number each time the ladder grows, and still rolls over once a far-dated market attracts real trading. The chart's span label is derived from the history's own first/last timestamps (`historySpanLabel()`, capped at 30d) — it used to be the hardcoded string `LAST 30 DAYS`, which claimed a 30-day span over the 8-day series: title + `by POLYMARKET` attribution row, big NOW figure (desktop only; dimmed when data >24h old — no textual stale badge), and a 30-day Lightweight Charts area chart (`MergerOddsChart.tsx`, auto-scaled; the sole chart on the Daily Feed since the stock chart was dropped 2026-08-03). The 1D/7D/30D delta row was replaced by the chart 2026-07-03 (deltas still computed in the JSON). Runs automatically on `fleet-scrape.yml` (3x daily, 03:00/11:00/19:00 UTC) as a `continue-on-error` step so a Polymarket outage can't block the robotaxi tracker scrape. **Since 2026-08-13 the tracker-scrape step is `continue-on-error` too, for the reverse reason**: it runs first, so its failure used to skip the merger-odds fetch and the commit entirely — a 2026-08-10 site redesign froze `merger-odds.json` for 3 days and dimmed the visible card while the tile the scrape feeds is hidden anyway. A final `Fail if tracker scrape failed` step (keyed on `steps.scrape.outcome`) re-fails the job after the commit, so a broken scraper shows red instead of going green. **As of 2026-08-13 this workflow effectively runs for the merger odds alone** — see Robotaxi Tracker Scrape for the hold.

## Contact Form (`worker/contact/`)
Reader-message button added 2026-08-20 — the site's first inbound channel. Square envelope button (Lucide `mail`, inlined, `rx` dropped for sharp corners, redrawn on a 20-unit grid so 2px strokes stay pixel-crisp) mounted twice in `src/App.tsx`: right-aligned in the mobile title row, and first in the desktop nav left of DAILY_FEED. Opens one shared `ContactPopup` instance (standard `bg-bg/60 backdrop-blur-md` overlay + green mobile `[BACK]` bar). Carries a periodic shine sweep since 2026-08-24 (`.shine-sweep` in `src/index.css`): at rest the button is `border-green/50 text-green/50`, byte-identical to an inactive nav tab, so it read as a fourth tab that had lost its label. A skewed translucent-green band crosses it with a synced faint glow, occupying only the first 18% of a 5s cycle and parked off-screen for the rest — an occasional glint, not a strobe; pauses on hover, off under `prefers-reduced-motion`. Resting colors left alone; bumping them to full green is the follow-up lever if it still reads as camouflaged.

**Deliberately one-way — no email anywhere in the path.** Optional name/handle, no reply address; readers wanting a conversation are pointed at `@theteslathesis` on X (worded "reach out to me", not "DM" — DMs are restricted to verified accounts).

Flow: popup → `POST` to the Cloudflare Worker at `https://ttt-contact.sham4n.workers.dev` → issue in the **private** `kris-ow/ttt-inbox` repo, label `reader-message`. Read them at github.com/kris-ow/ttt-inbox/issues; closing one marks it handled. **No notification fires** — the Worker files issues via a PAT acting as the owner, and GitHub never notifies you about your own activity, so the inbox must be checked deliberately.

Worker abuse controls: origin allowlist (both site hostnames + localhost for dev), hidden `website` honeypot (fills → `200` + silent discard, so bots see success), and 3/hour + 10/day per hashed IP in KV with TTL expiry (raw IPs never stored). Turnstile was deliberately skipped for v1 — small audience, private destination; adding it later is an insert after the honeypot check, not a rewrite. Reader text is wrapped in a computed-length fence so `@mentions` and Markdown stay inert.

Deploys run `npx wrangler deploy --config worker/contact/wrangler.toml` and authenticate with `CLOUDFLARE_API_TOKEN` from the **gitignored root `.env`** (wrangler v4 auto-loads it from the repo root — there is no OAuth session on this machine). The Worker is outside `npm run build` and outside `tsconfig.app.json`'s `include`, so neither vite nor `tsc -b` touches it.

⚠️ The `GITHUB_TOKEN` secret is a fine-grained PAT (Issues:RW on `ttt-inbox` only) and **expires within a year**. On expiry the Worker returns `delivery_failed`, the popup shows readers an error, and nothing alerts you — re-mint and re-run `npx wrangler secret put GITHUB_TOKEN --config worker/contact/wrangler.toml`.
